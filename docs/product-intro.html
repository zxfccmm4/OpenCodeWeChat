把微信变成 OpenCode 与 OMO 移动入口

OpenCodeWeChat 通过微信官方 ClawBot ilink API，把你的微信消息桥接到本地 OpenCode 会话。出门在外，也能在微信里发起规划、续跑任务、收发文件，并尽量完整地拿到长回复。

查看一键运行方式 了解 OMO 指令
微信即入口 聊天界面直接发起 AI 开发任务，文件、图片发过去就能处理。
完整回复保护 OpenCode SSE 辅助补齐，微信侧按普通文本完整分片到达。
本地 OpenCode 自动拉起本机 OpenCode 服务，故障自愈，延续本地工具链。

不是聊天转发器，而是可随身携带的开发入口

它把完整回复保护、双向媒体收发、OpenCode 会话、Oh My OpenAgent 上下文、故障自愈和图形控制台组合成一个可日常使用的工具。

01

手机上发起本地开发任务

微信消息会被转成 OpenCode prompt，本机自动创建会话并返回结果。你在路上也能安排排查、规划和总结。

02

长回复完整送达

订阅 OpenCode SSE 增量作为本地补齐来源，微信侧只发送完整普通文本，长回复按安全长度分片。

03

双向媒体收发

把文件、图片、视频发给 ClawBot，自动下载解密到本地收件箱供 OpenCode 处理；AI 的产物文件也能上传发回微信，手机端直接下载打开。

04

内置 Oh My OpenAgent 上下文

每次调用 OpenCode 都通过 system 字段加载 OMO、MCP、Skill 和会话规则，普通消息也会进入更完整的 agent 流程。

05

按指令智能路由 agent

#plan 优先 Prometheus，#start 与 #delegate 优先 Atlas，#team 与 #ulw-loop 优先 Sisyphus，让意图直接对应工作流。

06

浏览器图形控制台

双击打开本地 GUI：状态面板、启动/停止、页面内扫码登录、登出和实时日志，全程不用碰终端；另有三平台菜单启动器可选。

它解决的不是“能不能聊天”，而是 AI 开发能不能随时接上

很多 AI 工具已经足够强，但它们常被困在桌面终端里。OpenCodeWeChat 解决的是入口、连续性和可靠性这三个更日常的问题。

离开电脑后，任务就断了

灵感、问题和临时需求经常出现在路上、会议中或手机旁。把微信接到本地 OpenCode 后，用户可以先把任务发出去，让本机环境继续承接。

AI 有能力，但入口太重

终端、命令、agent 名称、上下文加载都需要记忆成本。这个项目把它们压缩成微信里的普通消息和少量前缀，让复杂工作流更容易被日常使用。

桥接工具最怕不可靠

OpenCode 服务死亡自动重建会话并重试，坏消息连续失败自动跳过并告知，配合游标保护、去重和 token 回退——通道挂了能自己爬起来，队列不会被堵死。

从一条微信消息，到一次本地 OpenCode 执行

OpenCodeWeChat 保持链路清晰：微信只负责输入输出，真正的模型、工具、agent 和本地上下文仍在你的机器上运行。

微信发消息 发文本、OMO 指令，或直接发文件、图片让 AI 处理。
ilink 长轮询 拉取消息并管理同步游标与去重；媒体自动下载解密到收件箱。
加载 OMO 上下文 构造 system prompt，注入 MCP、Skill 和工作流规则。
调用 OpenCode 自动拉起 opencode serve，订阅 SSE 增量；服务死亡自动重建。
微信分块收结果 长回复在生成完成后按普通文本完整分片送达，产物文件随后发回可下载。

我和 AI 的协作方式：人做判断，AI 做推进

这个产品本身就是用 AI 协作开发出来的：人负责目标、取舍和验收，AI 负责快速阅读代码、生成方案、实现改动和反复验证。

人

定义真实需求：微信入口要能日常使用，而不是只跑通 demo。

AI

快速梳理项目结构、OpenCode 接口变化和 Oh My OpenAgent 工作流，把变化落到代码里。

人

纠偏产品命名和语义，明确围绕 Oh My OpenAgent / OMO 的真实流程。

AI

补齐测试、文档、一键脚本和介绍页，并用本地渲染、类型检查、单测持续验证。

协作节奏： 1. 人提出场景和约束 2. AI 阅读代码并形成实现路径 3. AI 小步修改并验证 4. 人指出语义偏差或体验目标 5. AI 修正并沉淀为文档、脚本和测试 结果： 需求没有停留在想法里，而是变成可运行、可展示、可继续迭代的产品。

用短前缀触发 OMO 工作流

你不需要在微信里操作复杂面板，只要在消息前加一个轻量前缀，就能把意图映射到更合适的 Oh My OpenAgent 协作模式。

#plan

先由 Prometheus 风格拆解任务、识别歧义、输出计划。

#start

沿着最近一次 #plan 缓存继续执行，适合续跑计划。

#team

请求多成员协作、并行调查和最终汇总。

#ulw

进入 ultrawork，全自动推进排查、实现与验证。

#hyperplan

面向复杂任务生成结构化计划、关键假设和验证点。

#review

以代码评审视角优先找 bug、回归风险和缺失测试。

微信里发送： #plan 帮我给这个需求拆一个实现计划 #start 按刚才的计划继续做 #team 分头查这个回归，最后合并结论 #ulw 直接把这个问题从排查到修复都做完 桥接层自动选择可用 agent： Prometheus / Atlas / Sisyphus / Oracle

心得体会：AI 产品的价值，往往藏在最后一公里

做完这个项目之后，最明显的感受是：模型能力不是唯一瓶颈。真正影响使用频率的，是入口够不够轻、上下文能不能持续、工具链是否可靠。

好的 AI 工具要贴近人的工作流

开发者不可能永远坐在终端前。把 OpenCode 和 OMO 接到微信，本质上是在把 AI 能力放到人已经熟悉的沟通入口里。

协作不是让 AI 代替判断

人仍然要决定方向、优先级和质量标准。AI 最适合承担大量探索、改代码、补测试、写文档和重复验证的工作。

可靠性比炫技更重要

游标、去重、登录、跨平台启动这些细节不显眼，但它们决定产品是否能被持续使用。真正的亮点，是让复杂系统变得稳定可用。

从源码到日常使用，都尽量一键化

开发者可以直接从源码运行，也可以生成面向 macOS 与 Windows 的一键启动包，交付给不想碰命令行的人。

浏览器图形控制台

macOS 双击 OpenCodeWeChatGUI.command，Windows 双击 OpenCodeWeChatGUI.cmd，Linux 运行 OpenCodeWeChatGUI.sh。浏览器自动打开：扫码登录、启停通道、实时日志一站搞定。

./OpenCodeWeChatGUI.command

三平台菜单启动器

偏好终端的话，菜单式启动器覆盖登录、登出、启动、停止和打开 GUI 五个动作，macOS / Windows / Linux 全平台同款体验。

./OpenCodeWeChatLauncher.command

发布包一键分发

通过 package 脚本生成 macOS Apple Silicon、macOS Intel 与 Windows x64 启动包，包含主程序、登录工具、图形控制台和环境配置模板。

bun run package:all
